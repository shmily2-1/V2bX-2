# 在线配置、证书和原风格菜单

## 默认多节点自动配置

菜单1、菜单15或 `v2bx generate` 对每个节点读取四项：

~~~text
核心 (xray/sing/hysteria2) [sing]:
面板地址:
面板密钥（不回显）:
节点ID:
~~~

每个节点填写核心、面板地址、密钥和节点ID后，自动识别面板协议、读取域名/端口/跳跃范围，并复用或申请证书。之后选择是否继续添加下一个节点（Y/N）；选N后统一备份、写入配置并部署全部节点，默认设置开机自启。任一节点校验失败时不写入整批配置。仅当选择 `sing` 且节点是 Hysteria2 时，会额外出现可选的伪装站点地址输入；输入有效的 HTTP(S) 网址启用 sing-box Hysteria2 `masquerade` 反向代理，留空保留已有值/不启用，输入 `-` 清除已有值。此设置仅作用于 sing 核心，不改变 TLS 证书域名或面板节点域名。默认流程不再询问HTTP确认、证书方式、邮箱或DEPLOY，也不打印重复的安全提醒。邮箱为空，不生成虚假邮箱。

可在一次指引中连续配置多个节点；也可在已有配置基础上继续添加。相同面板、节点ID及协议更新已有节点并保留调优字段；其他节点和核心配置保留，不会因本次只新增一个节点而丢弃其他节点。不同面板的同ID节点使用不同证书目录。

TLS域名按面板server_name、tls_settings.server_name、host及原节点CertDomain顺序读取。必要域名缺失、IP地址代替域名、证书损坏或面板不可达时返回真实错误，不补造数据。已有HTTP/DNS/file证书配置继续使用；新证书默认HTTP-01，不要求额外DNS凭据。

HTTP面板直接连接。需要TCP80且被可识别的systemd服务占用时，自动临时停止并在成功/失败后恢复；独立进程使用pidfd执行TERM/KILL，无法自动恢复的独立进程存在服务中断风险。`--check-only`仍不改配置、不启动或停止服务。默认流程保留校验、失败回滚和错误退出码；“节点已启动”只表示本机部署检查通过，不等同于公网验收。

首次一键安装在交互终端中且尚无配置时直接进入节点指引；`--non-interactive`仅安装程序。已有配置的一键更新保持原配置及运行状态，需要配置时使用菜单1或15。每个节点后按 Y 再填写下一个节点，按 N 统一部署本次配置的所有节点。菜单18可单独新增节点，菜单19可查看/修改节点，菜单20可移除节点并重新部署剩余节点；移除节点时保留证书文件，避免误删共享证书。

高级向导仍可逐项填写协议/证书等选项；默认向导和高级向导都支持逐个添加多个节点，全部填写完成后统一预检和部署，不再要求 HTTP 风险词、端口释放词或 DEPLOY 确认。`--from-file` 和 `--edit` 保留已有显式调用方式。离线 `--root/--offline` 也保持独立，不连接生产面板。

## 完整配置（--advanced）

安装 Release 后执行 v2bx generate，或菜单15。菜单0编辑私有副本再执行在线预检；离线方式仍有 v2bx generate --offline，--root 隔离模式不连接面板、不申请证书、不操作宿主服务。

1. 填核心 sing / xray / hysteria2、面板地址、密钥、节点ID。可auto读取协议，绝不在节点创建面板用户。
2. 验证 UniProxy/config 和 UniProxy/user 的真实JSON；验证单监听端口、核心协议兼容。读取密钥不回显，错误URL不输出，禁止重定向。
3. HTTPS是默认安全边界；HTTP面板会直接继续配置并提示风险。指定HTTP公网面板意味着密钥会明文传输，建议另行升级面板HTTPS。
4. 按面板TLS设置配置证书。HTTP/DNS都沿用原项目内置lego申请Let's Encrypt；HTTP-01用TCP80，不是UDP443。要求域名正确解析、可达的AAAA、公网TCP80云安全组和主机规则。已有证书会验证有效期、域名、链及私钥匹配。密钥0600；不使用自签名替代公共证书。
5. 证书条款、配置替换和服务启动自动继续。备份原配置，临时禁用失败重启，停止旧进程再原子写入。最多等待240秒，验证实际PID、监听端口和证书；成功默认开机自启。
6. 失败/正常中断时停止新进程，恢复原配置与旧服务。新签发证书保留，防止重复签发。SIGKILL、断电、磁盘故障不能保证回滚；检查 /run/systemd/system/V2bX.service.d/90-v2bx-provision.conf 和0600备份，修复后再尝试。切勿循环重试CA限流。
7. 服务运行不等于完整上线验收，仍需从公网客户端验证TLS、认证、代理流量、跳跃及面板计费。

## TCP80占用与已有证书复用

重新配置相同面板、节点ID/协议和域名时，向导会校验并复用既有证书、私钥路径及ACME配置，避免仅因生成新目录而重复签发。长于续期窗口的有效HTTP证书不要求临时清空TCP80。不同域名/节点、无效证书、符号链接或已分配给其他节点的证书路径不会自动复用。

确实需要HTTP-01签发/近期续期而TCP80被占用时：

1. 同时检查IPv4/IPv6，显示PID、程序名和systemd服务名，不显示可能含密钥的进程参数。权限错误不会误判成占用。
2. 对可安全识别的systemd服务自动临时停止；网站可能短暂中断，部署成功、失败或正常中断后均尝试恢复原服务，不disable、不改防火墙。
3. 非托管独立进程自动使用Linux pidfd锁定原进程，先TERM等待5秒，仍占用才KILL；**这类进程无法自动恢复**，不支持pidfd的内核/Python会拒绝。容器、socket/timer激活、受保护系统服务等仍会拒绝自动处理。
4. --check-only绝不释放端口。发生SIGKILL、断电等无法执行finally的情况，需要按屏幕打印的systemctl start命令人工恢复；恢复失败返回错误，不报告完整上线成功。
5. **自动续签不会永久保存释放TCP80的权限。** 托管服务恢复后如果继续占用80，未来HTTP续签仍会冲突；长期共用80请选DNS-01或人工配置可共存的证书方式。不要为了测试反复请求生产CA。

旧命令仍可保留 `--release-http-port`、`--kill-http-port` 和 `--yes` 参数以兼容；端口释放和部署现已自动执行。例如：

~~~bash
v2bx generate --from-file /root/node.json --release-http-port --yes
~~~


## 自动部署

可调用 v2bx generate --from-file /root/node.json --public-ip PUBLIC_IP --yes。该文件必须root拥有、0600、普通文件，使用仓库扁平Cores/Nodes结构；不能把密钥作为命令行参数。--check-only只进行预检（会打开运行时互斥锁文件），不改配置/服务/申请证书。--no-enable可不新增开机自启；--timeout范围15–900秒。

HTTP面板不再要求 --allow-insecure-panel；使用HTTP会继续并在输出中提示密钥明文风险。Hysteria2允许 --allow-empty 启动等待授权；其它协议仍拒绝空名单启动。空Hysteria2节点必须拒绝所有认证；200空用户数组会撤销全部用户，304保留原列表。

在线向导使用标准JSON与扁平节点配置，不自动展开Include/ApiConfig/Options；自定义核心配置和自定义ExecStart请人工迁移后预检。它不会改面板监听端口；server_port和跳跃范围以面板最新API为准。

## 菜单（0–17）

| 编号 | 功能 |
|---|---|
|0|修改配置：私有副本、在线预检、部署|
|1|安装后逐个填写节点信息，Y可继续添加，N后统一部署|
|2|只更新程序与管理组件，不重新配置/启动|
|3|彻底卸载：直接删除配置、证书、ACME账户和本项目备份|
|4 / 5 / 6|启动 / 停止 / 重启|
|7 / 8|状态 / 跟随日志（Ctrl-C结束）|
|9 / 10|设置 / 取消开机自启|
|11|安装最新发行版内核、启用BBR|
|12 / 13|版本 / X25519密钥|
|14|升级维护组件（从同一已校验Release连同二进制更新，旧进程不自动重启）|
|15|逐个配置节点并合并部署|
|16|直接放行全端口并保留精确回滚状态|
|17|退出|

菜单实时读取systemd显示是否运行/开机自启，不写死“已运行”。不在测试节点自动执行卸载或破坏性操作。

## 重装、删除范围与多个节点

默认流程每次填写一个节点后询问是否继续（Y/N），选N后统一预检并部署本次添加的所有节点。完整向导使用 `v2bx generate --advanced`，可额外填写协议和证书细节，也支持Y/N逐个添加节点。

菜单1和v2bx install成功安装程序后进入多节点自动指引，菜单2只更新组件。默认指引在本次流程中逐个验证并增量合并节点，按 N 后整体部署且保留其他节点；完整向导仍是生成/替换整套配置，需重新填写要保留的节点。每个节点使用独立证书路径，监听端口和跳跃范围需避免冲突。菜单0可编辑已有Nodes并整体预检。

菜单3直接彻底卸载。范围包含/etc/V2bX（包括配置备份、证书私钥、ACME账户和运行数据）、/usr/local/lib/V2bX-2、/var/backups/V2bX-2，以及安装记录中的二进制、识别出的服务/drop-in、管理别名和安装器格式的备份。仅删除项目目录和已识别文件，不递归删除共享程序目录；外部证书的符号链接只删除链接本身。逃逸的父路径、目录中的挂载点、自定义服务会拒绝自动处理。

保留数据请执行v2bx uninstall --keep-config；配置、证书、ACME账户和数据备份保留。彻底删除后重装需要重新签证书，频繁测试可能触发CA限流。卸载不会清空全机防火墙或卸载系统内核。

新版同一菜单中可直接“3卸载→1安装”：缺失的安装器会从本仓库固定标签恢复，失败立即停止。已经运行的旧版菜单不能热替换代码，看到旧版127错误时先17退出，再重新执行GitHub一键入口并打开v2bx。

## BBR / 内核（11）

最新指Debian/Ubuntu/dnf发行版已配置签名源的候选内核，不是任意第三方mainline。菜单选择后直接执行；保留旧内核，不自动重启。BBR可用后写独立sysctl配置并核验，失败撤回sysctl；内核包安装本身不自动卸载。目标机器已经使用BBR时，无需为节点上线重装内核。

## 全端口放行（16）

菜单选择后直接执行并保留新增规则状态。它不flush、不关闭防火墙或SELinux，不删除Hysteria2 NAT，不开放云安全组。

支持原生nftables输入过滤链与简单iptables环境。每个nft input basechain分别插入ACCEPT；不能靠新表覆盖其它DROP。存在UFW/firewalld管理器、混合legacy/nft、前置过滤等复杂情况会拒绝并要求人工处理，不声称全放行。没有input过滤链时报告本机未拦截，不添加无意义规则。只开TCP/UDP，不改ICMP/转发策略。

规则是临时的，重启/防火墙reload可能失效；状态和备份在 /var/backups/V2bX-2/。终端显示精确撤回命令。生产节点通常只需要相应UDP范围+TCP80，请勿为方便暴露数据库/管理端口。

## 验证边界

scripts/test-provision.py使用真实本地HTTP服务器和文件事务，systemd/CA/防火墙动作由隔离替身覆盖；不把这些称作生产验收。实际节点部署另记录证书、稳定服务、真实公网客户端和端口跳跃结果。BBR安装/全开放仅测取消、拒绝、命令构造及隔离网络命名空间，不在生产机为测试升级内核或开放所有端口。
