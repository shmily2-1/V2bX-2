# v0.1.0-core-upgrade.7：彻底卸载 / 同菜单重装 / 首次多节点指引

这是 prerelease / 验收版。本次只修复安装管理流程，保持 .6 的 Go 数据面和三套内核版本，不移动旧标签。

## 本次变化

- 修复同一管理菜单内卸载后选择 1 时，本地 install.sh 已删除导致错误 127。缺少安装器时，从本仓库固定标签恢复临时安装器，先检查 Shell 语法，再使用同一 Release 的 ZIP + SHA256 校验安装；失败不进入配置向导、不假报成功，临时文件退出时清理。
- 菜单 1 / v2bx install 安装成功后必定进入首次配置指引。逐个填写核心、面板、密钥、节点 ID、证书，可在“继续添加节点”选择 y；在线确认 DEPLOY 后才替换配置、申请/复用证书并启动。
  每次只填写一个节点，然后提示“是否继续添加节点？(Y/N) [N]”：Y/y添加下一个，N/n或回车结束添加，最后统一预检与确认部署。
- 菜单 2 / v2bx update 和菜单 14 仍然只更新组件，不重新配置、不自动启动或重启节点。
- 菜单 3 默认改为彻底卸载，必须输入 UNINSTALL-ALL。删除本项目配置、证书/私钥、ACME 账户、项目备份、已识别程序和服务、管理组件及安装器生成的备份。旧确认词 UNINSTALL 不会执行彻底删除。
- 若明确需要保留数据，使用 v2bx uninstall --keep-config，再输入 UNINSTALL。共享证书目录的符号链接只删除链接，不追删目标；自定义服务、逃逸路径或路径内的挂载点会拒绝自动删除。
- 卸载先检查路径/服务并获取安装和配置互斥锁；先收集命令别名再删除，避免链式 v2bx 别名残留。不会递归删除共享程序目录，不清空宿主防火墙，不卸载系统内核。
- 增加同菜单重装、多节点首次向导、独立入口重装、私密文件清除、取消/保留、下载/语法失败及外部文件保护回归。

## 旧菜单恢复

已经在 .6 或更早的菜单中看到错误 127：先输入 17 退出。旧 Bash 进程不会因为磁盘文件更新自动换成新代码，再运行：

~~~bash
wget -N https://raw.githubusercontent.com/shmily2-1/V2bX-2/v0.1.0-core-upgrade.7/install.sh && bash install.sh
v2bx
~~~

菜单 1 会进入首次多节点指引。更新已有正常节点请用菜单 2，避免把整套配置误当成单节点追加操作。

## 注意事项

- **彻底卸载不可撤回。证书删除后需要重新签发，频繁卸载/重装可能触发 CA 限流。** 建议先自行离线备份；菜单明确列出删除范围。
- 配置向导可以一次配置多个节点，但这是整套配置的生成/替换，不会自动把新节点追加到旧配置。节点端口/跳跃范围不能冲突，在线向导要求每个节点独立证书路径。
- HTTP 面板需确认明文风险；HTTP-01 要求公网 TCP 80，不等于节点 UDP 443。自动续签机制保留。
- 隔离 --root 模式仍然离线，不连接生产面板、不申请真实证书、不调用宿主服务。真实服务器的既有配置和证书不会为了卸载回归测试被删除。
- 详见 docs/ONLINE-PROVISION.md 和 docs/INSTALL.md；源码/回环/隔离回归不等同于所有协议、所有用户环境的长期生产验收。
